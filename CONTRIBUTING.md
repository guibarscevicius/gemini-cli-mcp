# Contributing to gemini-cli-mcp

Thanks for your interest in improving gemini-cli-mcp. This document covers how to
build, test, and propose changes.

## Development setup

```sh
npm install
npm run build      # tsc — must pass before committing
npx tsc --noEmit   # standalone type check
npm test           # vitest — all tests must pass
```

The SQLite-backed session store emits an `ExperimentalWarning` under Node's
`node:sqlite` module in test output; it is not an error.

## Making changes

- Keep changes focused and minimal — fix the root cause rather than papering over it.
- Match the style and conventions of the surrounding code.
- Add or update tests for any changed logic.
- Document any new environment variable, MCP tool, resource, or exported symbol in
  `README.md` and `AGENTS.md`.

## Hands-on integration testing

Unit tests cover isolated logic, but real MCP tool calls against the local build
catch spawn, session-wiring, and output-parsing issues that mocks cannot. Before a
pull request leaves draft, exercise the affected tool(s) against a local build
(`dist/index.js`). See `AGENTS.md` for the standard scenario checklist, and add a new
scenario when you add a feature.

## Commit messages

This project's changelog and releases are generated by
[release-please](https://github.com/googleapis/release-please), which reads
[Conventional Commits](https://www.conventionalcommits.org/) prefixes:

- `feat:` — a new user-visible capability
- `fix:` — a bug fix
- `refactor:` — internal restructuring with no user-visible change
- `docs:`, `test:`, `chore:` — as named

Any commit that **removes or renames a public surface** (an MCP tool name, resource
URI, environment variable, or exported symbol) must use `feat!:` or include a
`BREAKING CHANGE:` footer, so the change is reflected in the changelog.

## Pull requests

Open pull requests as drafts. Include a summary and a hands-on test plan. Link any
issue the change closes with a `Fixes #<n>` line.

## Reporting bugs and vulnerabilities

Open an issue for ordinary bugs. For security issues, follow [`SECURITY.md`](SECURITY.md)
— do not file a public issue.
